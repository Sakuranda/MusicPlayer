# 手机播放与界面修复验收（2026-09-05）

## 发现与处理

线上 `ssh yxai`（`/opt/musicplayer`）原先运行 `85c075b`。随机播放没有 30/40 秒计时切歌逻辑，自动切歌来自音频 `ended`；未取得用户 iPhone 的原始事件日志，所以不能认定单一因素已完全解释实机现象。

- 165 个现有音频都是带 `moof` 的 DASH 分片文件，Mutagen 读到头部时长为零，FFprobe 却可读取完整音频。下载流程过去只改扩展名、写标签，未规范化封装。这是实际发现的主要兼容性风险。现在入库前无损复制 AAC 包到普通 faststart M4A，前后逐包 SHA-256 比较、保留标签与封面/歌词，原子替换。
- 部分数据库时长错误：例如 ID 167 记录 592 秒，实际音轨约 296 秒。现在以实际文件为准。
- 浏览器 `ended` 过去直接跳歌，队列和锁屏元数据依赖 React effect。现在使用同步队列游标与稳定系统动作处理器；异常提前结束提示重试，不消费下一首，旧 `play()` 失败不得覆盖新曲状态。
- Media Session 保留播放/暂停、上一曲/下一曲及进度拖动，释放快进/快退动作。系统上一曲直接切歌，网页上一曲保留播放超过 3 秒先回到开头的行为。
- 曲库刷新网络失败不再卸载播放器。手机底栏显示切歌按钮，展开页提供封面、歌名和歌词；修复图片随进度反复挂载、开关定位、顶部/底部安全区。
- 鉴权比较改用 UTF-8 bytes，防止 Unicode 输入触发 500；限制验证码缓存；CSV 防止公式注入。
- 深蓝/柔紫视觉、新 SVG Logo、PNG 主屏幕图标及 manifest 已上线。主屏幕模式仍需要网络，没有离线缓存。

FFmpeg 官方说明普通 MP4 相比碎片封装兼容性更好，并支持 faststart 把索引移到文件前部：[FFmpeg formats](https://ffmpeg.org/ffmpeg-formats.html)。系统切歌与进度动作遵循 [Media Session 规范](https://www.w3.org/TR/2026/WD-mediasession-20260605/)。
